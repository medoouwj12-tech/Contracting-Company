# عقار | Aqar Kuwait

نظام عربي RTL لإدارة العقارات والعملاء والطلبات والمتابعات لشركة عقارية في الكويت. قاعدة البيانات والمصادقة المستهدفتان هما Neon Postgres وNeon Auth، مع سياسات وصول داخل PostgreSQL.

## الموجود في النسخة الحالية

- لوحة رئيسية، العقارات والعملاء، المواعيد والمتابعات، الإعلانات، التقارير، الإعدادات والأدوار.
- استيراد Excel وCSV عبر Web Worker، والتحقق من ملف تجريبي يتجاوز 50 ألف صف.
- استيراد دفعات إلى Neon Data API عبر RPC، بسياسات للتكرار وإمكانية التراجع عن الإنشاءات والتحديثات.
- جلسات دخول Neon Auth، إنشاء ملف صلاحيات ابتدائي للمستخدم، وحماية جداول PostgreSQL بسياسات RLS.
- لا يعرض Neon أرقام الهواتف مباشرة؛ يكشفها إجراء مسجل بعد إدخال تعليق، ويحفظ هوية المستخدم ووقت الاطلاع.
- مواعيد بمكان داخلي أو خارجي، وأرشفة العقارات والعملاء مع تعليق واسم الأرشِف ووقت الحذف، مع الاستعادة من سلة المحذوفات للمدير.
- رسائل موظفين وتعاميم، بصلاحيات إرسال منفصلة وروابط HTTPS للمرفقات.
- المفضلة محفوظة لكل مستخدم في Neon عند تفعيل الاتصال.
- جلسات حضور تبدأ وتنتهي من حساب الموظف، مع سجل للفريق وخيار المدير لإنهاء الجلسة.
- قوائم عمل سريعة للعقارات التي ينقصها الموقع أو بيانات التواصل، وآخر ١٠٠ سجل.
- تحرير إحداثيات الخريطة وفتحها على الخرائط من ملف العقار.
- بيانات الموقع المنظمة تشمل المنطقة والقطاع والتوزيع والقطعة والقسيمة والشارع.
- بيانات شركة مشتركة قابلة للطباعة مع ملفات العقارات.
- ملفات «العقار المطلوب» بمعايير العميل والمنطقة والنوع والمساحة والسعر وحالة المطابقة.
- مطابقة تلقائية عند إنشاء طلب أو إضافة عقار مطابق، مع إشعار الموظف وإظهار نسبة المطابقة بحسب المعايير.
- شاشة بحث موحدة بفلاتر حقول العقار والعنوان والتاريخ والمساحة والسعر والعميل، مع بحث الهاتف المسجل بصلاحية وتدقيق.
- حفظ عنوان العميل التفصيلي وإرفاق صورة العقار في Neon ضمن حد رفع مناسب للـData API.
- مركز إشعارات لعمليات الإسناد، مع حالات القراءة والأرشفة والاستعادة وانتهاء الصلاحية بعد ٦٠ يومًا.
- سير عمل طلبات الإعلان للنشر أو استكمال البيانات أو الحذف المؤقت لمدة ٦٠ يومًا.
- إعدادات النشر على Vercel وملفات ترحيل قاعدة البيانات في `database/migrations`.

تحتاج بعض وظائف الربط الخارجي إلى إعداد حسابات الشركة ومفاتيحها، مثل تفعيل Neon Auth ورفع ملفات المرفقات إلى خدمة تخزين. يجب تطبيق ملفات الترحيل على قاعدة Neon التابعة للشركة قبل الاستخدام الفعلي.

## التشغيل المحلي

المتطلبات: Node.js 20 أو أحدث.

```powershell
npm install
Copy-Item .env.example .env.local
npm run dev
```

## ربط Neon

1. أنشئ مشروعاً وقاعدة بيانات وفرعاً في Neon.
2. فعّل **Neon Auth** و**Neon Data API** على الفرع وقاعدة البيانات نفسيهما.
3. انسخ عنوان Neon Auth إلى `NEON_AUTH_BASE_URL` و`NEXT_PUBLIC_NEON_AUTH_URL`.
4. انسخ عنوان Data API إلى `NEXT_PUBLIC_NEON_DATA_API_URL`.
5. أنشئ قيمة عشوائية سرية بطول 32 حرفاً أو أكثر وضعها في `NEON_AUTH_COOKIE_SECRET`. هذا متغير خادمي فقط.
6. ضع اتصال Postgres المباشر في `DATABASE_URL` لتطبيق الترحيلات. لا تضف بادئة `NEXT_PUBLIC_` إلى بيانات الاتصال.
7. طبّق بالترتيب `database/migrations/001_neon_initial_schema.sql` ثم ملفات `002_video_contact_audit.sql` و`003_recycle_bin.sql` و`004_staff_messaging.sql` و`005_contact_access_report.sql` و`006_work_sessions.sql` و`007_property_work_queues.sql` و`008_company_profile.sql` و`009_property_requests.sql` و`010_notifications_center.sql` و`011_ad_request_workflow.sql` و`012_property_map_editor.sql` و`013_property_location_codes.sql` و`014_request_auto_matching.sql` و`015_client_addresses_and_search_media.sql` و`016_employee_management.sql` و`017_sales_client_claims_and_shared_comments.sql` على قاعدة Neon بعد تفعيل Neon Auth؛ الترحيل يربط `profiles.id` بهوية `neon_auth.user.id` ويستخدم `auth.user_id()` في سياسات RLS. ترحيلات 015 و016 و017 مطبقة على قاعدة المشروع المتصلة وقت التجهيز.
8. يحصل أول مستخدم على دور مدير النظام تلقائياً عند تهيئة ملفه. استخدم التحديث اليدوي التالي فقط إذا كانت قاعدة قديمة تحتوي عدة ملفات مستخدمين ولا يوجد فيها مدير نظام:

   ```sql
   update public.profiles
   set role_id = (select id from public.roles where name = 'super_admin'),
       phone_visible = true,
       price_visible = true
   where email = 'admin@your-company.com';
   ```

إعداد المصادقة والبريد الإلكتروني، وأصول الصور والمستندات، يتم من خدماتها المخصصة؛ Neon هنا يوفر Postgres وAuth وData API، ولا يحل محل تخزين الملفات.

## الأمان

- لا تضع `DATABASE_URL` أو `NEON_AUTH_COOKIE_SECRET` في متغيرات `NEXT_PUBLIC_*`.
- سياسات الصفوف والصلاحيات موجودة في PostgreSQL، وبيانات المستخدمين في Neon Auth.
- أول دخول ينشئ ملف مستخدم بدور `viewer`؛ يجب ترقية حساب المدير الأول يدوياً كما في الخطوة السابقة.
- لا تستخدم وضع المعاينة المحفوظ في المتصفح لبيانات الشركة.

- `npm run typecheck` — فحص TypeScript
- `npm run build` — بناء الإنتاج
- `npm run test:import` — اختبار محلل ملف Excel التجريبي
